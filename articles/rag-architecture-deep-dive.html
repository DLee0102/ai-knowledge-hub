打通私域知识与大语言模型之间的“最后一公里”，构建高召回、低幻觉的企业级问答系统。

端到端 RAG 核心流水线

生产级 RAG 不只是简单的“切片 + 向量搜索”，而是由离线索引与在线检索生成两大阶段构成的精密管道：

STEP 1 · 离线 文档解析与分块

OCR/版面还原、语义切分、保留父子层级与元数据。

STEP 2 · 索引 双路索引构建

Embedding 稠密向量索引 + BM25 倒排稀疏索引。

STEP 3 · 召回 查询改写与混合检索

Query Expansion / HyDE + RRF 多路召回融合。

STEP 4 · 精排 Cross-Encoder 重排

对 Top-50 候选精细打分，筛选 Top-5 高相关片段。

STEP 5 · 生成 引用溯源生成

约束 LLM 基于上下文作答并标注出处，降低幻觉。

分块策略（Chunking）对比与交互体验

分块过小会丢失上下文语义，分块过大会稀释向量表示并引入无关噪声。常见策略如下：

分块方式 核心思想 适用场景
固定字符 + 重叠 (Fixed + Overlap) 按固定长度切分，相邻块保留 10%~20% 重叠窗口 快速原型、结构较均匀的纯文本文档
递归语义分块 (Recursive) 优先按标题、段落、句号层级切分，尽量保持语义完整 Markdown、技术手册、知识库文章（最常用）
父子文档检索 (Parent-Child) 用小块做精准检索，命中后将完整大块（父块）送入 LLM 长文档问答，兼顾高检索精度与丰富上下文
上下文增强 (Contextual Retrieval) 离线用小模型为每个分块补充全局摘要前缀再向量化 财务报告、法律条文等强依赖上下文指代的文档

混合检索（Hybrid Search）与 RRF 融合

纯向量检索擅长语义同义匹配（如“苹果手机”匹配“iPhone”），但对专有名词、错误码、型号（如 CUDA_ERROR_700、Qwen2.5-72B）往往召回不佳； 而 BM25 关键词检索 恰好擅长精确字面匹配。

工业界普遍采用 倒数排名融合（Reciprocal Rank Fusion, RRF） 将两路结果无量纲合并：

RRF_Score(d) = 1 / (k + rank_vector(d)) + 1 / (k + rank_bm25(d)) （通常取常数 k = 60）

合并得到 Top-50 候选后，再使用 Cross-Encoder Reranker（如 BGE-Reranker、Cohere Rerank）把 Query 和 Document 拼接输入 Transformer 做深度交叉注意力打分，通常能让 Top-5 准确率提升 10%~25%。

RAG 效果评测黄金三角（RAG Triad）

  • Context Relevance（上下文相关性）：检索回来的文档片段是否真的包含回答问题所需的依据？
  • Groundedness / Faithfulness（忠实度）：模型生成的回答是否完全忠于检索内容，没有凭空编造（幻觉）？
  • Answer Relevance（回答相关性）：最终回答是否直接、完整地解决了用户的原始提问？
