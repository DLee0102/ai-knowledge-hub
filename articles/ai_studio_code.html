02

Transformer 是如何“堆叠”成几十上百层的？

堆叠的核心秘密是把所有层挂在同一条残差流（Residual Stream）主干道上：每层只负责读取状态、算出增量修正 +Δ 再写回主干道，同时靠 Pre-Norm 保证反向传播梯度畅通无阻。

03

因果语言建模（Causal LM） vs. 双向建模（Bidirectional）

两者本质的架构分水岭只在于注意力掩码（Attention Mask）的不同——但就是这一张小小的掩码矩阵，直接决定了模型能否高效训练、能否用上 KV Cache 以及最擅长什么任务。

交互实验 3：联动注意力可见性矩阵 悬停或点击任意行
行 = 当前正在计算的词（Query），列 = 可被参考的词（Key）
因果语言建模（Causal LM） 下三角掩码 · GPT / DeepSeek

严禁偷看未来：右上三角置为 -∞，经 Softmax 变为 0。

双向建模（Bidirectional / MLM） 全可见矩阵 · BERT / Embedding

全局视野：任意位置均可同时关注左侧与右侧全部 Token。

因果建模（支持 KV Cache） 单步复杂度 O(L)
双向建模（KV Cache 彻底失效） 单步全量重算 O(L²)
同一条 7 词训练语料，单次前向传播产生多少有效 Loss 信号？
双向 MLM 不能直接预测下一词（会泄题），必须随机遮盖 ~15% 的词做完形填空。
因果建模：Next-Token Prediction 100% 位置计算 Loss

借助下三角因果掩码，一次并行前向计算即可同时用 第1词→猜第2词、前2词→猜第3词 …… 所有 6 个预测位置全部产生有效梯度，数据算力利用率拉满！

双向建模：Masked LM（完形填空） 仅 ~15% 位置计算 Loss

只有被替换为 [MASK] 的极少数位置会计算交叉熵损失，其余约 85% 的 Token 只当陪跑上下文；且引入了训练有 [MASK]、真实推理无 [MASK] 的分布差异。

04

全景对比与架构收敛结论

一表看懂两种建模范式的分工边界，以及为何通用大模型最终走向统一。

对比维度 因果语言建模（Causal LM） 双向建模（Bidirectional / MLM）
典型代表模型 GPT、Claude、Gemini、DeepSeek、Qwen、Llama BERT、RoBERTa、DeBERTa、BGE/E5 向量模型、ViT
主流网络结构 Decoder-Only（仅解码器堆叠） Encoder-Only（或 Encoder-Decoder 的编码端）
注意力视野 单向（仅看左侧上文 + 自身，右侧严格屏蔽） 双向（同时融合左侧上文与右侧下文全部线索）
训练样本利用率 极高（~100% Token 产生梯度），公式：∏ P(xₜ | x<ₜ) 较低（仅 ~15% 被遮盖词产生梯度），存在 [MASK] 失配
KV Cache 兼容性 原生完美兼容：历史词表示永不因新词改变，支撑高效 Prefill + Decode 天然不兼容：末尾每添一个新词，所有历史 Token 表示全部失效重算
最佳应用场景 开放式文本/代码生成、多轮对话、长思维链推理（CoT）、通用 Agent RAG 文本向量检索（Embedding）、重排（Reranker）、文本分类、视觉编码
01

训练算力效率碾压

万亿 Token 预训练中每个词都贡献监督信号，且凭借下三角掩码依然可整句高度并行训练，无须串行等待。

02

推理工程的基石

严格因果性是 KV Cache 成立的前提。没有因果掩码，就无法在 Prefill 缓存后以低延迟逐字 Decode。

03

万物皆可“续写”统一

问答、翻译、编程、工具调用乃至深度慢思考，全都能统一成 Prompt → Response 续写，天然适配 RL 后训练。

04

双向建模并未消失

双向架构依然是 RAG 检索向量（Embedding）、精排模型（Reranker）与多模态视觉编码器（ViT）的黄金底座。
