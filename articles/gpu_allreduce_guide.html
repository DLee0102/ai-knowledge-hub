从集合通信家族到 Ring-AllReduce 与大模型实战

多卡训练和推理大模型时，成百上千张 GPU 不能各自闷头算，必须高频“对账汇总”。AllReduce 就是多卡世界里最重要、最频繁的一条神经动脉——把所有卡上的局部结果规约求和，并让每一张卡都同步拿到完整总和。

01

一句话看懂 AllReduce，以及它和“兄弟们”的区别

拆开名字就秒懂：Reduce（规约）指把多张卡上相同位置的数字合并（最常见是求和 Sum 或求平均 Avg）；All（全部）指最终结果不是只交 给 1 张主卡，而是每一张 GPU 都拿到一份完全相同的最终汇总结果。

02

工业界王牌算法：Ring-AllReduce（环形全规约）

如果让所有 GPU 都把数据发给 GPU 0 求和再广播回去，GPU 0 的网卡会瞬间堵爆（耗时随卡数 N 暴涨）。天才的 Ring-AllReduce 把 N 张卡连成一条单向环形接力赛道，将张量切成 N 块，拆成 Reduce-Scatter（N-1 步）+ AllGather（N-1 步），让所有卡的带宽同时 100% 跑满！

硬件带宽、跳数延迟与算法耗时对比计算器

虽然 Ring-AllReduce 在带宽上近乎完美（2S/B），但当 GPU 扩到 64~256 张、且单次张量很小（如 TP 推理的激活值）时，Ring 绕圈的跳数延迟 2(N-1)·α 就会暴露短板——这正是现代 NCCL 引入 Tree-AllReduce（双二叉树） 与 NVLink Switch 硬件网内规约（SHARP） 的原因！

公式说明（α = 单跳启动延迟，B = 单向有效带宽）：
• 朴素中心化 Master：2(N-1)·(S/B + α)（主卡带宽成死结）
• Ring-AllReduce：2·((N-1)/N)·(S/B) + 2(N-1)·α（大张量带宽最优）
• Tree-AllReduce (NCCL)：2·(S/B) + 2·log₂(N)·α（大集群小张量低延迟）
• NVLS 网内硬件规约：交换机芯片直接做加法，流量趋近 1·S/B！
